## PR #1 — 임대인 주민등록번호의 국외이전을 끊는다

### 문제 (재확인)

사진/PDF를 업로드하면 **원본 이미지가 그대로 Google LLC(OCR)로 전송**된다. 거기엔 임차인 본인뿐 아니라
**임대인의 주민등록번호**가 들어 있다.

| 개인정보보호법 §28조의8① 예외 | 임차인 본인 정보 | **임대인 정보** |
|---|---|---|
| 1호 정보주체 별도 동의 | 가능 | **불가** — 임대인은 이용자가 아니라 동의를 받을 수단이 없다 |
| 2호 법률·조약 근거 | 없음 | 없음 |
| 3호 가목 계약 이행에 필요한 처리위탁 | **가능** | **불가** — 임대인과 우리 사이에 계약이 없다 |
| 3호 나목 정보주체 이익 | 해당 안 됨 | 해당 안 됨 |
| 4호 개인정보보호 인증 | 미보유 | 미보유 |
| 5호 적정성 결정 국가 | 미국은 해당 안 됨 | 미국은 해당 안 됨 |

→ **임차인 정보는 3호 가목으로 적법, 임대인 정보만 근거가 없다.** 전면 중단이 아니라 **한 사람의 정보만**
빼면 끝난다는 뜻이다.

### 왜 "정규식 마스킹"으로 안 되는가

마스킹을 **OCR 결과 텍스트에** 걸면 이미 원본 이미지가 국외로 나간 뒤다. 위반은 전송 시점에 성립하므로
사후 마스킹은 법적으로 **아무 효과가 없다.** 이미지를 읽기 전에 번호 위치를 알아야 하는 선후 모순이 있다.

### 설계 3안

#### A안 — OCR을 국내 사업자로 교체 (1순위)

국외이전 자체가 사라지므로 §28조의8 적용이 **배제**된다. 임대인 정보 문제가 근본에서 없어진다.

- 후보: 네이버 클로바 OCR / 카카오 OCR / 업스테이지 Document AI (전부 국내 리전)
- 구현: `lib/ocr/` 에 어댑터 인터페이스를 두고 공급자를 환경변수로 선택
  ```
  interface OcrProvider { recognize(buf: Buffer, mime: string): Promise<OcrResult> }
  OCR_PROVIDER=clova | google
  ```
  기존 Google 호출부를 `GoogleOcrProvider` 로 그대로 감싸 두면 롤백이 환경변수 한 줄이다.
- **Anthropic(특약 자연어 해석)은 남겨도 된다.** 거기로는 이미지가 아니라 텍스트만 가는데,
  그 텍스트에서 아래 정규식으로 주민번호·성명을 제거하면 국외로 나가는 항목에서 빠진다.
  ```
  /(?<!\d)\d{6}\s*[-–—]?\s*[1-4]\d{6}(?!\d)/g   // 주민등록번호 13자리
  /(?<!\d)\d{6}\s*[-–—]?\s*[5-8]\d{6}(?!\d)/g   // 외국인등록번호
  ```
  치환은 삭제가 아니라 `●●●●●●-●******` 같은 고정 토큰으로 — 룰 판정이 "번호란이 비어 있음"을
  결함으로 오판하지 않게.
- 선행 확인 필요: 단가, 계약서 사진(기울어짐·필기) 정확도. **A/B 로 실측 후 전환.**

#### B안 — 업로드 전 브라우저 내 마스킹 강제 (A안 배포 전 임시 차단막, 즉시 적용)

- 업로드 직후 `<canvas>` 미리보기에서 **임대인 인적사항 영역을 드래그로 가리지 않으면 제출 비활성화**
- 전송은 canvas 에서 다시 인코딩한 이미지로만 (원본 File 객체를 절대 그대로 보내지 않는다)
- 가린 영역은 실제 픽셀을 덮어쓴다 — CSS 오버레이는 전송 데이터에 반영되지 않으므로 금지
- 한계: 국외이전은 남고(임차인 정보는 적법), 사용자가 잘못 가리면 유출. **A안의 대체가 아니라 가교.**

#### C안 — 온디바이스 사전 탐지 (비권장)

tesseract.js/WASM 로 브라우저에서 13자리 패턴을 찾아 자동 블러. 공수가 크고 **놓치면 그대로 유출**되어
위반 리스크를 기술 정확도에 의존하게 만든다.

### 결론 — 2단 배포

1. **오늘**: B안을 올려 번호가 더 이상 나가지 않게 막는다.
2. **A안 실측 후**: OCR 국내 전환으로 근본 제거 → B안의 강제 마스킹은 선택 기능으로 완화.

### 수용 기준

- [ ] 전송 페이로드를 네트워크 탭에서 캡처해 **주민번호가 보이지 않음**을 눈으로 확인
- [ ] Anthropic 요청 본문에 13자리 패턴이 0건 (로깅 테스트로 검증)
- [ ] 마스킹 미수행 시 제출 버튼 비활성 (E2E 1건)
- [ ] 정규식 유닛테스트: 하이픈 유무, 공백, 전각 하이픈, 외국인등록번호 — 각 1건
- [ ] 개인정보 처리방침 제6조의 국외 수탁자 목록을 실제 구성과 일치하게 갱신

## PR #2 — AI 이용 고지 (AI기본법 §31①)

### 문제

개인정보 처리방침이 **Anthropic PBC·Google LLC 를 국외 수탁자로 이미 명시**하고 있어 생성형 AI 사용은
다툴 수 없는 사실이다. FAQ 에도 「특약사항의 자연어 위험 해석」이 적혀 있다.
§31① 고지 누락은 **조사 절차 없이 과태료 3천만원**이 가능한 유형이다. 문구 한 줄이 비용 대비 가장 싼 방어다.

### 넣을 것

1. **결과 화면 상단 상시 배너** (접히지 않고, 스크롤해야 보이지 않는 위치)
   > 이 판정은 생성형 AI 가 포함된 자동 분석 결과입니다. 법률 자문이 아니며, 최종 판단은 이용자에게 있습니다.
2. **업로드 전 1회 고지** — 사전 고지 성격을 맞추기 위해 파일 선택 화면에도 같은 취지 한 줄
3. **FAQ / 이용약관에 사용 단계 명시** — 어디에 AI 가 쓰이는지 단계별로
   | 단계 | 사용 기술 | 사람의 개입 |
   |---|---|---|
   | 문자 인식 | OCR | 없음 |
   | 조항 판정 | 규칙 193개 (AI 아님) | 없음 |
   | 특약 해석 | 생성형 AI | 없음 |
4. **면책 문구 재작성** — 현재의 「법률 자문이 아니다」식 **책임 배제**는 약관법 §7 로 무효 위험이 있다.
   배제가 아니라 **채무 범위 한정**으로 쓴다.
   - 피할 문구: "어떠한 책임도 지지 않습니다"
   - 쓸 문구: "본 서비스가 제공하는 것은 ⟪등록된 193개 규칙에 따른 조항 대조 결과⟫이며, 개별 사안에
     대한 법률 의견의 제공을 채무로 하지 않습니다."
5. **가격표 내리기** (변호사법 §112 3호) — 결제를 닫아 둔 것만으로는 부족하다. 금액이 적힌 요금 섹션 자체를
   비공개로. 이건 PR #2 에 묶어 같이 처리.

### 수용 기준

- [ ] 결과 화면·업로드 화면 양쪽에서 고지가 **첫 화면에** 보인다 (스크린샷)
- [ ] 약관에 "책임을 지지 않는다" 형태의 전면 배제 문구가 0건 (grep)
- [ ] 금액이 표기된 요소가 공개 경로에 0건 (grep + 실제 페이지 확인)
